# lane: x509

A DER reader and an X.509 certificate parser: the structure the TLS client checks. Parsing
only. Signature checks, chain building and hostname matching come in a later lane that
builds on this. BearSSL's "minimal" X.509 engine is the model: decode what you need,
reject what you don't understand when it's marked critical.

## Files you own

`lib/chaki/asn1.bend`, `lib/chaki/x509.bend`, `test/chaki_asn1_check.bend`,
`test/chaki_x509_check.bend`.

## API (exact)

```python
# asn1.bend
type Tlv is Data:
  Tlv{tag: U32, value: List<&2, U32>, rest: List<&2, U32>}

# one DER element from the front of b: tag is the identifier octet (low-tag-number form
# only). Strict DER: definite minimal lengths only, long form up to 4 length bytes.
def read(b: List<&2, U32>) -> Maybe<&2, Tlv>

# every element of a constructed value's contents, in order; None when one doesn't parse
def items(b: List<&2, U32>) -> Maybe<&2, List<&2, Tlv>>

# an OBJECT IDENTIFIER's contents as dotted text, "1.2.840.113549.1.1.11"
def oid(value: List<&2, U32>) -> String

# an INTEGER's contents without the sign-padding 0x00 (for unsigned values)
def uint(value: List<&2, U32>) -> List<&2, U32>

# UTCTime (tag 0x17, YYMMDDHHMMSSZ; YY < 50 is 20YY) or GeneralizedTime (0x18,
# YYYYMMDDHHMMSSZ) as Unix seconds; None for other forms, or before 1970 / after 2106
def time(tag: U32, value: List<&2, U32>) -> Maybe<&2, U32>

# x509.bend
type Cert is Data:
  Cert{der: List<&2, U32>, tbs: List<&2, U32>, sig_alg: String, sig: List<&2, U32>,
       issuer: List<&2, U32>, subject: List<&2, U32>, not_before: U32, not_after: U32,
       key_alg: String, key_curve: String, key: List<&2, U32>, dns: List<&2, String>,
       ca: Bool, path_len: U32, key_usage: U32, unknown_critical: Bool}

def parse(der: List<&2, U32>) -> Maybe<&2, Cert>

# the modulus and exponent of an RSAPublicKey (a Cert's key when key_alg is rsaEncryption)
def rsa_key(key: List<&2, U32>) -> Maybe<&2, List<&2, U32> & List<&2, U32>>

# r and s of a DER ECDSA-Sig-Value
def ecdsa_sig(sig: List<&2, U32>) -> Maybe<&2, List<&2, U32> & List<&2, U32>>
```

Fields of `Cert`:

- `der`: the whole certificate. `tbs`: the TBSCertificate element, header included (it's
  what the signature covers).
- `sig_alg`: the outer signatureAlgorithm OID. `sig`: the signature BIT STRING's bytes (0
  unused bits required).
- `issuer` and `subject`: the raw DER of each Name, header included, compared as bytes.
- `key_alg`: the SubjectPublicKeyInfo algorithm OID. `key_curve`: the namedCurve OID for
  id-ecPublicKey, otherwise `""`. `key`: the subjectPublicKey BIT STRING's bytes.
- `dns`: the SAN dNSName entries, lowercased.
- `ca` and `path_len`: from basicConstraints (path_len 4294967295 when absent).
- `key_usage`: bit n of the KeyUsage BIT STRING (RFC 5280 numbering, digitalSignature = 0,
  keyCertSign = 5) is bit n of the U32, and 4294967295 when the extension is absent.
- `unknown_critical`: any extension marked critical other than basicConstraints
  (2.5.29.19), keyUsage (2.5.29.15), subjectAltName (2.5.29.17) and extKeyUsage
  (2.5.29.37).
- Version 3 only (v1 and v2 roots exist, so a v1 cert parses, with no extensions).

## Fixtures

Generate them with `openssl` on this machine and paste them into the check as hex (`openssl x509
-outform DER | xxd -p -c 1000`). They are synthetic, so they're fine in a public repo. Keep
the commands in a comment in the check, so they can be regenerated.

- an RSA-2048 self-signed root (CA:TRUE, keyCertSign);
- an EC P-256 intermediate signed by it (CA:TRUE, pathlen:0);
- an EC P-384 leaf signed by the intermediate, with SAN `DNS:cha.test, DNS:*.Cha.TEST`;
- a v1 certificate;
- one with a critical nameConstraints extension.

## Checks

- `test/chaki_asn1_check.bend`: short and long lengths, rejects for non-minimal and
  indefinite lengths and a high-tag-number form, OID text for rsaEncryption and
  ecdsa-with-SHA384, both time forms (with the 2049/1950 split), uint stripping.
- `test/chaki_x509_check.bend`: every field of every fixture against what `openssl x509
  -text` says (state those values in the check), `tbs` and `sig` bytes extracted exactly,
  `rsa_key` of the root and `ecdsa_sig` of the leaf, and None for a truncated certificate
  and one with trailing junk.
