# lane: x509v

Certificate path validation: is this chain, sent by a server, trusted for this host right
now? BearSSL's minimal X.509 engine is the model. It's small and strict, and it fails closed
on anything it doesn't understand.

## Builds on

`x509.bend` (parse), `rsa.bend`, `ecdsa.bend`, `sha2.bend`, `b64.bend` (pem), and
`sys.bend` (files go through Base's `File` effects).

## Files you own

`lib/chaki/x509v.bend`, `test/chaki_x509v_check.bend`, `test/chaki_x509v_live.bend`.

## API (exact)

```python
# every CERTIFICATE block of a PEM bundle that parses
def anchors(pem: String) -> List<&2, X509.Cert>

# the system's trust anchors: $SSL_CERT_FILE, else the first of
# /etc/ssl/certs/ca-certificates.crt, /etc/pki/tls/certs/ca-bundle.crt, /etc/ssl/cert.pem
# and /etc/ssl/ca-bundle.pem that reads. Fail when none does.
def load() -> IO(Result<&1, &1, U32 & String, List<&2, X509.Cert>>)

# whether cert's signature verifies under issuer's public key
def signed_by(cert: X509.Cert, issuer: X509.Cert) -> Bool

# whether host matches the certificate: SAN dNSName entries only, case-insensitive, a "*."
# leftmost label matches exactly one non-empty label, no other wildcards, and an IP literal
# host never matches
def host_ok(cert: X509.Cert, host: String) -> Bool

# chain: DER certificates as the server sent them, leaf first. Done{Unit} when trusted,
# Fail{reason} otherwise: one short line naming what failed and which certificate.
def verify(chain: List<&2, List<&2, U32>>, anchors: List<&2, X509.Cert>, host: String, now: U32) -> Result<&1, &1, String, Unit>
```

## Rules

- Build the path from the leaf: the next certificate is whichever of the sent certificates
  or the anchors has `subject` equal to the current `issuer` (byte for byte) and whose key
  verifies the current signature. Stop at the first anchor. At most 8 certificates. The
  server's order isn't trusted, and extra certificates are ignored.
- The leaf and every intermediate: `not_before ≤ now ≤ not_after`, and no
  `unknown_critical`. Anchors aren't time-checked (RFC 5280 §6: an anchor is trusted
  information, not a certificate).
- The leaf and every intermediate: `server_auth` (no extKeyUsage, or one naming
  serverAuth or anyExtendedKeyUsage). A certificate issued only for another purpose, say
  clientAuth or code signing, isn't a TLS server's or an issuer's. Anchors aren't
  EKU-checked either.
- Each intermediate: `ca` true, `key_usage` absent or with keyCertSign, and `path_len` not
  exceeded by the intermediates below it.
- The leaf: `host_ok`.
- Signatures: sha256/384/512WithRSAEncryption (PKCS#1 v1.5) and ecdsa-with-SHA256/384/512
  over P-256 and P-384. Anything else (RSASSA-PSS-parameterized certificates included) fails
  with "unsupported signature algorithm".

## Checks

- `test/chaki_x509v_check.bend`. Synthetic chains made with `openssl` (commands in a comment),
  frozen at a fixed `now`:
  - root RSA-2048 → intermediate EC P-256 (pathlen 0) → leaf EC P-384 for `cha.test` and
    `*.cha.test`;
  - a second leaf under RSA directly.
  Trusted: the good chains; the chain sent in the wrong order; extra junk certificates.
  Refused, each with its reason:
  - an expired leaf (and one not yet valid);
  - the wrong host, and `a.b.cha.test` against `*.cha.test`;
  - an intermediate without CA, and one without keyCertSign;
  - a pathlen violation;
  - a tampered signature;
  - a missing intermediate;
  - an unknown critical extension;
  - a leaf whose extKeyUsage is clientAuth only;
  - an empty chain.
  `host_ok` on its own: wildcards, case, `cha.test.` with a trailing dot (normalize it, or
  refuse it, and say which), and an IP literal.
- `test/chaki_x509v_live.bend` (by hand): `load()` reads the system store (more than 100
  anchors). The chains of api.github.com, codeberg.org and example.com verify at
  `Sys.now()`. Fetch them at run time with `Process.run("openssl", ["s_client",
  "-showcerts", ..])` and decode the PEM. Don't commit live certificates.
