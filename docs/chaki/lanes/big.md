# lane: big

Big natural numbers for RSA and ECDSA verification. BearSSL's i31 code is the model: plain
limbs, Montgomery multiplication, no cleverness past that.

## Files you own

`lib/chaki/big.bend`, `test/chaki_big_check.bend`, and optionally
`scripts/chaki-big-vectors.ts` (a bun script that prints the expected values with BigInt).

## API (exact)

A number is a `List<&2, U32>` of 16-bit limbs, least significant first, with no high zero
limbs. Zero is `[]`.

```python
def of_bytes(b: List<&2, U32>) -> List<&2, U32>            # big-endian bytes
def to_bytes(n: List<&2, U32>, len: U32) -> List<&2, U32>  # big-endian, exactly len bytes (left zero padding; high bytes dropped if it doesn't fit)
def of_u32(x: U32) -> List<&2, U32>
def bits(n: List<&2, U32>) -> U32
def is_zero(n: List<&2, U32>) -> Bool
def cmp(a: List<&2, U32>, b: List<&2, U32>) -> Cmp
def add(a: List<&2, U32>, b: List<&2, U32>) -> List<&2, U32>
def sub(a: List<&2, U32>, b: List<&2, U32>) -> List<&2, U32>         # a - b when a >= b, else zero
def mul(a: List<&2, U32>, b: List<&2, U32>) -> List<&2, U32>
def divmod(a: List<&2, U32>, b: List<&2, U32>) -> List<&2, U32> & List<&2, U32>   # b non-zero
def mod(a: List<&2, U32>, m: List<&2, U32>) -> List<&2, U32>
def modadd(a: List<&2, U32>, b: List<&2, U32>, m: List<&2, U32>) -> List<&2, U32>  # a, b < m
def modsub(a: List<&2, U32>, b: List<&2, U32>, m: List<&2, U32>) -> List<&2, U32>
def modmul(a: List<&2, U32>, b: List<&2, U32>, m: List<&2, U32>) -> List<&2, U32>
# m odd and above 1
def modexp(b: List<&2, U32>, e: List<&2, U32>, m: List<&2, U32>) -> List<&2, U32>
# p an odd prime, a not a multiple of p
def modinv(a: List<&2, U32>, p: List<&2, U32>) -> List<&2, U32>
```

If Montgomery form helps ECDSA (many multiplications mod one prime), also export it: a
`Mont` context of your design, with `mont(m)`, `mont.mul`, `mont.to` and `mont.from`.

## How

- 16-bit limbs make every limb product fit in a U32. Carry explicitly.
- `modexp` uses Montgomery multiplication (CIOS or a similar shape) with a left-to-right
  square-and-multiply. An RSA public exponent is 65537, so that path must be fast.
- Tail calls throughout. Keep each def small: native builds reject wide defs.

## Checks

`test/chaki_big_check.bend`, with expected values from BigInt (generated by your bun script,
pasted as hex):

- round trips of `of_bytes`/`to_bytes`;
- add, sub, mul, divmod and mod on random operands of 1, 2, 17, 64, 256, 2048 and 4096 bits,
  and zero, one, and powers of two;
- modexp with e = 65537 against a 2048-bit and a 4096-bit modulus, and with a 256-bit
  exponent against the P-256 prime;
- modinv against the P-256 and P-384 primes and group orders.

Report how long a 4096-bit modexp with e = 65537 takes on the JS lane and natively. The
targets are under 3 s and under 100 ms.
